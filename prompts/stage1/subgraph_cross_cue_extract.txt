你是知识图谱三元组抽取专家。下面给出**同一讲次内一段连续课堂文本窗口**（由多段按时间顺序拼接）。单段内关系已另行抽过；你只补**跨段合起来才成立、或前文框架 + 后文成员才齐备**的概念关系。

## 核心原则
1. **只抽跨段边**：某一单段内两端实体与关系都已说清的，不要再抽。
2. **勿重复仅指「全名 SPO 完全相同」**：`已有边` 里已有 `A-rel-B` 时不要再输出同一条。  
   **不同主语/宾语的平行边必须补**（见下方「分类/并列补齐」）——已有 `成员₁-belong_to-类` **不表示** `成员₂-belong_to-类` 已覆盖。
3. **允许隐含衔接**：口语指代、承上启下、「和前面一样」「同理」「第二种/下一种」等，不必有跨段 verbatim 连写依据。
4. **优先具体抽象关系**：能判定归属/组成/依赖时，用 `belong_to` / `part_of` / `depend_on` / `property_of` / `synonym_of`；`related_with` 仅作无法归类时的兜底（少用）。

## 优先补齐的跨段模式（通用，按出现尽量覆盖）
在配额内，优先输出下列模式（有则抽，无则跳过；不要编造窗口中未出现的概念）：

1. **分类 / 枚举 / 并列补齐**  
   前文给出类、框架、清单或「共 N 种/第几种」；后文才出现具体成员、变体、对称情形。  
   → 每个后文成员补对前文类/框架的 `belong_to`（或类对成员的 `part_of`，二选一保持方向一致）。  
   → 已有边里只有部分成员时，**补齐其余成员**，不要因为同类已有一条就停手。

2. **「同模式 / 同理 / 一样」继承**  
   后文说与前文某概念「一样的模式 / 同样写法 / 对称 / 对偶 / 类似」时：把前文已建立、且仍适用的归属或依赖边，迁到后文新概念上（换 subject/object，关系类型通常不变）。

3. **框架先行、成员后至**  
   前文引入方法、范式、系统、翻译套路、公理系统等；后文才给出步骤、子类型、组成部件。  
   → `成员/步骤 -belong_to|part_of-> 框架` 或 `框架 -depend_on-> 前提概念`。

4. **指代与省略承接**  
   后文用「它 / 这种 / 上述 / 该形式 / 刚才的」回指前文实体，并陈述性质、组成或依赖。  
   → 解析指代后写出完整 SPO。

5. **定义拆段**  
   前文抛出术语，后文才给定义、充要条件或形式化要件。  
   → `概念 -depend_on|part_of|property_of-> 要件`（按语义选关系）。

## 不要抽取
- 编号公理/定理**实例**、例题推导链、作业题号
- 纯字母串实体 a,b,c / x,y,z（正式术语全名除外）
- 与「已有边」**全名 SPO 完全相同**的边
- 窗口文本中完全未出现、也无法由指代唯一还原的实体

## 关系方向
- `depend_on` / `part_of` / `belong_to` / `property_of` / `synonym_of` / `related_with`（少用）
- `property_of`：属性 → 拥有者；「具有*」必须 `object_to_subject`

## 输出约束（重要）
- **context 必须输出空字符串 `""`**（跨段边不绑原文摘录）
- description 用一句话点明「前文哪类信息 + 后文哪类信息」如何衔接；勿抄长文
- subject/object：能对应「已知实体」或「已有边」端点时**原样复制全名**；否则「中文/英文」
- 配额用满前，优先上述模式 1–2（分类补齐与同理继承），再写其他跨段边

## 字段
- abstract_relation, concrete_relation（1–8字）, statement_direction, attribute_category
- 每个窗口最多 {max_triples} 条；确认无跨段关系时才 {{"triples": []}}
