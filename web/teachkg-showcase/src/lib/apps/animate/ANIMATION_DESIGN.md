# 动画引擎设计规范（制作前必读）

> 目标：先设计分镜与叙事，再写生成器。禁止「先画条形图再补树」。

## 1. 总原则

1. **一种主视觉**：每个精制引擎只选一种主隐喻（树 / 图遍历 / 着色），全程贯彻。
2. **文字服务画面**：每帧先想「观众看到什么变化」，再写说明；说明要具体到数值与对象名。
3. **可对照课内**：优先用解析出的课内实例；没有则用文档写明的默认例，并标注「示意例」。
4. **分镜表先于代码**：改引擎前先改本文件对应「分镜表」，再改 `engines`。

## 2. 帧契约（AnimFrame）

| 字段 | 用途 | 写法要求 |
|------|------|----------|
| `caption` | 大标题 | ≤18 字，动词开头（选出/合并/回溯…） |
| `detail` | 当前状态摘要 | 含具体对象与数值，如 `选 B(2) 与 D(1)` |
| `definition` | 原理一句 | 稳定复述核心定义，勿每帧大改 |
| `analysis` | 详细分析 | 2～4 句：为何这一步、和贪心/正确性关系 |
| `delta` | 相对上帧 | 明确「什么变了」 |
| `tip` | 易错 / 对照 | 可选；给错误做法或复杂度 |
| `nodes/edges` | 主画面 | 精制引擎以图/树为主，避免中途换隐喻 |
| `hud` | 舞台结构条 | 队列 / 栈 / 森林权值，必须画在图上而非只写旁白 |
| `bars` | 仅辅助 | **哈夫曼禁用**；归结可用 |

## 3. 视觉语言

- **active**：本帧焦点（脉冲）
- **frontier**：候选 / 队列或栈中（尚未处理完）
- **done**：已处理完 / 已弹出
- **idle**：尚未发现或未参与
- 边标签：哈夫曼左 `0` 右 `1`；遍历的绿边表示生成树

BFS 禁止把「刚入队」标成 done；DFS 禁止把「还在栈上」标成 done。

## 4. 哈夫曼分镜表（全程树）

**主隐喻**：森林 → 不断合并 → 单棵前缀树。  
**禁止**：频率条形图作为主画面。

默认例：`A:5, B:2, C:3, D:1`（或课内频率）。

| # | 画面 | caption | detail / analysis 要点 |
|---|------|---------|------------------------|
| 0 | 4 棵单节点树横排 | 初始森林 | 每符号一棵树；权=频率 |
| 1 | 高亮权最小两棵 | 选出最小两棵 | 为何是它们；若选错会怎样 |
| 2 | 新生父节点，两棵挂上下 | 合并成新树 | 新权=之和；放回森林；0/1 边 |
| 3… | 重复选+合并 | … | 每步写清当前森林权值列表 |
| 终 | 单棵完整树 | 前缀树完成 | 示范一条编码路径；最优性一句 |

布局：对当前森林中每棵树做分层布局，多棵树水平并排，间距随棵数缩放。

## 5. 其它引擎（摘要）

- **BFS/DFS**：主隐喻=图；文字写清队列/栈内容。
- **着色**：主隐喻=图+色号；每帧写邻居已用色。
- **归结**：主隐喻=子句集合（可用条）；文字写清消去的互补对。

## 6. 制作流程

```
选题 → 写分镜表（本文件）→ 定默认例与课内解析
  → 实现生成器 → scripts 模拟抽查帧文案与结构
  → 舞台验收（是否全程主隐喻）
```
